# ADR-0001: 采用领域模块化单体和公开端口

- 状态：Accepted
- 日期：2026-07-11

## 背景

Token Farmer 的农场、钱包、支付和模型网关共享强事务不变量，但它们的变化频率与数据所有权不同。过早拆成独立微服务会引入分布式事务；把所有逻辑放入一个无边界应用又会让模块互相修改数据。

## 决策

采用模块化单体。Web、API 和 Worker 是独立运行进程；`auth`、`wallet`、`gateway`、`farm`、`social`、`payment`、`leaderboard` 和 `admin` 是编译期受约束的领域模块。

每个模块拥有业务逻辑和表，只通过根 `index.ts` 暴露 Application Port。跨模块原子操作共享 `db-runtime` 的事务上下文，但每个模块仍通过自己的 Repository 修改自己的表。非关键投影使用事务 Outbox。

## 后果

- 可以使用单个 PostgreSQL 事务守住偷取、收获、支付和余额不变量。
- 必须维护严格的依赖检查，否则模块化只是目录命名。
- 排行榜等投影允许最终一致；账本和果实结算保持强一致。
- 以后只有在边界稳定、有独立容量需求并解决跨服务一致性后，才考虑拆分服务。
