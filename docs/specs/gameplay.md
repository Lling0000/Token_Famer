# Gameplay Specification

## 1. 范围与权威性

本文定义第一版电脑端农场、成长、维护、好友、偷取、萌犬和排行榜的可观察行为。经济单位、收获金额和准备金见 [`economy.md`](economy.md)，HTTP 路径与错误见 [`api.md`](api.md)。

服务器是土地状态、成熟时间、事件、随机结果、好友资格、偷取数量和奖励的唯一权威。客户端倒计时、按钮状态和预估值只用于展示，每次写操作都重新读取服务器状态。

## 3. 等级与土地

### 3.1 账号等级

- 初始等级为 1、经验为 0。
- 从当前等级升到下一级需要 `100 * currentLevel^2` 经验。
- 一次收获获得 `5 * cropLevel * landExperienceMultiplier` 经验，使用整数向下取整。
- 等级上限为 15；满级仍可累计审计经验，但展示值停在满级进度。
- 帮助好友每次获得 2 经验，每个上海自然日最多 20 次计奖；超过仍可帮助但不发经验或花瓣。
- 首次完成一个真实维护事件获得 1 经验；同一事件的失败重试不重复发经验。

升级在产生经验的事务内完成。一次大量经验可以连续升多级，土地解锁随后立即可用。

### 3.2 地块数量

| 玩家等级 | 可用地块 |
| -------: | -------: |
|        1 |        6 |
|        2 |        8 |
|        3 |       10 |
|        4 |       12 |
|        5 |       14 |
|        6 |       16 |
|        7 |       18 |
|        8 |       20 |
|        9 |       22 |
|    10-15 |       24 |

新地块在升级事务内创建为空闲状态。24 格是第一版硬上限。降级不受支持，冻结账号也不删除土地。

### 3.3 土地品质

土地有 1 至 3 级品质，初始为 1：

| 品质 | 产量倍率 | 基础时长倍率 | 经验倍率 | 解锁等级 |
| ---: | -------: | -----------: | -------: | -------: |
|    1 |     100% |         100% |     100% |        1 |
|    2 |     105% |          98% |     105% |       11 |
|    3 |     110% |          96% |     110% |       15 |

升级成本使用花瓣，具体数值属于发布的土地配置。升级只允许在地块空闲时进行；已经播种的 Planting 保存播种时土地快照，不被后续升级改变。

## 4. Planting 生命周期

状态机：

```text
empty -> growing -> mature -> harvested -> empty
                 \-> cancelled (仅未扣款的事务失败，不是用户操作)
```

第一版成熟作物不会因等待自动枯萎。`withered` 视觉资源保留给未来规则，不得在没有新 Spec 和规则版本时启用。

### 4.1 播种

播种事务必须：

1. 校验账号、地块空闲、等级、模型启用、规则版本和幂等键。
2. 通过 WalletService 扣除种子成本并预留平台最大奖励负债。
3. 从 CSPRNG Adapter 取得 32 字节 seed，保存密文 seed 并公开 commit。
4. 保存作物、模型、土地、价格、成长和随机规则快照。
5. 创建 35% 与 70% 两个事件检查任务和 Outbox。

commit 为 `SHA-256(seed || plantingId || ruleVersionHash)` 的小写十六进制。相同幂等请求返回同一个 Planting 和 commit；刷新、Worker 重试和任务重复投递不得更换 seed。

### 4.2 成长阶段

客户端按服务器返回的 `planted_at`、`matures_at` 和当前服务器时间展示：

|          进度 | 阶段           |
| ------------: | -------------- |
|   `[0%, 20%)` | 种子           |
|  `[20%, 45%)` | 幼苗           |
|  `[45%, 70%)` | 成长           |
| `[70%, 100%)` | 开花           |
|     `>= 100%` | 成熟/丰收/变异 |

事件和恶作剧可能增加 `matures_at`，化肥可能减少它。客户端不能只根据原始时长判定成熟。

## 5. 成长事件与维护

### 5.1 事件生成

在原始成长进度 35% 和 70% 各检查一次。每次使用从 Planting seed 按固定标签派生的独立随机值：

- 70%：无事件。
- 10%：缺水。
- 10%：杂草。
- 10%：虫害。

重复 Worker 不得生成第二个同阶段事件。事件一经生成就有唯一 ID、类型、出现时间、状态和规则版本。

### 5.2 处理

- 缺水：一次免费操作必定解决。
- 杂草/虫害：每次免费尝试有 70% 成功率，每个事件最多两次免费尝试。
- 两次免费尝试用尽后，可以支付该 Planting 种子成本的 1% 保证解决；使用整数向上取整，最少 1 Token。
- 自己和好友都能免费处理；保证解决费用只能由土地主人支付。
- 同一事件并发操作锁定事件，只有第一个有效成功得到奖励，其他请求返回最新状态而不重复扣费或发奖。

未解决事件的影响：

- 每个缺水或杂草事件在其检查点给 `matures_at` 增加基础成长时长的 10%；之后解决不追回已经增加的时间。
- 每个成熟时仍未解决的虫害，把收获分布中的 10 个百分点从 100% 档移动到 50% 档，最多两个事件、共 20 个百分点。
- 事件不直接修改模型、种子成本、偷取预算或 Token 单价。

### 5.3 化肥

- 化肥使用花瓣购买，不使用模型钱包。
- 每次将“操作时剩余时长”减少 10%，使用整秒向下取整。
- 每茬最多使用 3 次，即最多进行三次连续的剩余时间缩减；不声称等于原始时长 30%。
- 化肥不能把成熟时间改到当前时间之前；最早为操作事务时间。
- 价格和每日购买限制来自不可变道具配置。

## 6. 成熟与收获

- 达到权威 `matures_at` 后，任何状态读取都可以幂等推进为 `mature`；不依赖 Worker 准时执行。
- 成熟时按 seed 和播种规则确定 50%、100%、110% 或 145% 档。110% 使用丰收花表现，145% 使用变异花并写入图鉴。
- 成熟响应公开 seed、规则哈希、随机抽样值和结果档，客户端可以重算 commit 与档位。
- 成熟后的前 10 分钟为主人独占期，好友不能偷；主人可立即收获。
- 收获锁定 Planting，按当前 `left_fruit_num` 创建主人 Token 包、结算准备金、发经验并置为 `harvested`。
- 一键收获逐块调用相同 Use Case；单块失败不回滚其他成功地块，响应逐块列出结果。

## 7. 好友与亲密度

### 7.1 好友关系

- 每个用户有不可变好友码；昵称搜索返回最少必要资料。
- 好友申请状态为 `pending/accepted/rejected/cancelled`，重复申请幂等。
- 接受后双方各计一个好友关系，单方最多 50 个已接受好友。
- 删除好友立即结束关系，但保留偷取和账本审计；重新添加重新计算 24 小时保护期。
- 拉黑会删除待处理申请/现有关系，阻止双方搜索详情、申请、帮助、恶作剧和偷取。
- 邀请链接只预填目标好友，不绕过注册邀请码、邮箱验证或对方接受。

### 7.2 保护期

- 新账号从邮箱验证完成起 72 小时内不能成为偷取目标，也不能偷别人。
- 新好友从接受时间起 24 小时内不能互相偷取或恶作剧，但可以查看和帮助。
- 成熟后主人独占 10 分钟。
- 保护判断使用服务器 UTC 时间，边界达到时允许操作。

### 7.3 亲密度

亲密度是双方关系内的双向共享点数。成功浇水、除草或除虫增加 1 点；同一人对同一事件最多一次，每个用户每天最多从帮助获得 20 点。

| 等级 | 累计点数下限 | 偷取基础成功率 |
| ---: | -----------: | -------------: |
|    0 |            0 |            35% |
|    1 |           20 |            41% |
|    2 |           60 |            47% |
|    3 |          140 |            53% |
|    4 |          300 |            59% |
|    5 |          600 |            65% |

删除好友不删除历史点数审计，但重新建立关系从 0 点开始。

## 8. 动态偷取

### 8.1 成熟预算

每个 Planting 成熟时使用独立随机值抽取最大可偷百分比：

| 随机区间（0-9999） | 概率 |          最大预算 |
| -----------------: | ---: | ----------------: |
|             0-4499 |  45% | `fruit_num` 的 5% |
|          4500-7499 |  30% |               10% |
|          7500-8999 |  15% |               20% |
|          9000-9799 |   8% |               30% |
|          9800-9999 |   2% |               40% |

`max_stealable_fruit = floor(fruit_num * percentage / 100)`。结果为 0 时该地不可偷。该字段只在服务端保存；普通客户端只看到 `stealable`，不看到预算百分比。

### 8.2 资格

一次尝试必须同时满足：

- 双方是已接受好友且未拉黑。
- 双方账号和好友保护期已结束，目标已经过主人独占期。
- Planting 为成熟、未收获、可偷且仍有偷取预算。
- 该好友没有尝试过这一地块这一茬，无论此前成功或落空。
- 发起者在当前上海自然日少于 20 次偷取尝试。

好友列表中的“可偷 N”是满足资格的地块数量，不是可获得果实数。

### 8.3 结算顺序

一次尝试使用三个从服务端 seed 派生且写入审计的整数随机值：狗拦截、成功、数量档。

1. 若主人有有效萌犬守护，40% 概率抓住；被抓则本次为 0，尝试仍被消耗。
2. 未被抓时，按亲密度表决定成功；失败为 0，尝试被消耗。
3. 成功后按数量档计算候选数量：

| 数量档随机区间（0-9999） | 概率 |                               候选数量 |
| -----------------------: | ---: | -------------------------------------: |
|                   0-5999 |  60% |   `max(1, floor(fruit_num * 1 / 100))` |
|                6000-8999 |  30% | `max(1, floor(fruit_num * 25 / 1000))` |
|                9000-9999 |  10% |   `max(1, floor(fruit_num * 5 / 100))` |

实际数量是候选数量、剩余偷取预算和 `left_fruit_num` 三者最小值。若并发后预算为 0，结果为 `BUDGET_EXHAUSTED` 且不生成 Token 包。

服务端保存：

- `fruit_num`：本茬成熟总果实。
- `left_fruit_num`：主人尚未收获且未被偷的果实。
- `stole_num`：累计成功偷走数量。
- `stealers`：所有已尝试玩家及结果的投影。
- `stealable`：当前资格/预算综合状态。
- `steal_intimacy_level`：尝试时亲密度快照。

始终满足 `left_fruit_num + stole_num = fruit_num`（主人收获前）。主人收获后 Planting 进入终态并保存 `owner_harvested_num = left_fruit_num`，最终满足 `owner_harvested_num + stole_num = fruit_num`。

### 8.4 萌犬

- 狗粮用花瓣购买，提供 1、3 或 5 天守护；三种只改变持续时间，初始抓捕率均为 40%。
- 新狗粮把 `guard_until` 延长对应持续时间，不提高抓捕率；从 `max(now, guard_until)` 起计算。
- 抓捕只令本次尝试归零，不扣偷取者钱包、不转移额外 Token，也不保证追回历史果实。
- 抓捕率属于版本化配置，改变只影响新尝试并记录规则版本。

## 9. 帮助与恶作剧

- 好友可以处理目标真实存在的免费维护事件；不能代付保证解决费用或替主人收获。
- 双方都开启“允许恶作剧”后，每个好友每个上海自然日最多对对方放置一次虫草。
- 虫草增加目标 Planting 基础时长的 5%，同一 Planting 累计最多增加基础时长 10%。
- 恶作剧不改变收获档、`fruit_num`、偷取预算、价格、经验或钱包；主人可以立即移除，但不追回已增加时间。
- 拉黑或关闭开关会阻止新恶作剧，不追溯删除已发生的审计记录。

## 10. 排行榜

三个榜单：

- **农场净收获**：期间内农场主人与偷取 Token 包的价值，减去播种和保证维护成本；欢迎赠送、购买和 API 退款不计入。
- **API 消耗**：期间内最终结算的实际 API charge；预留不计，退款/冲正按账本方向抵扣。
- **当前持有**：快照时钱包可用、钱包预留和未激活 Token 包的总 Token Score；不包含平台准备金。

不同模型按事件发生时的 Model Price Version 转为整数 Token Score。榜单提供全服/好友以及上海时区日榜、周榜（周一 00:00 开始）、总榜。

持有榜默认隐藏。玩家主动加入后只显示向下取整的整数分数；退出后从下一次快照移除。日/周前 3 获得称号，前 10 获得像素头像框，不发模型 Token。

排行榜是事件投影，允许短暂延迟。页面显示快照时间；它不能作为账本或钱包事实来源。

## 11. 电脑端交互

- `64x32` 等距地块，像素资源使用整数倍缩放，24 格农场保持稳定画布。
- 桌面结构为顶部资源栏、中央无装饰边框农场、右侧好友栏、底部工具栏；商城、仓库和排行榜使用抽屉或独立工作区。
- 鼠标拖动画布、滚轮缩放、悬停显示状态；所有图标按钮有可访问名称和 Tooltip。
- 小于 1180px 宽度显示电脑端提示，不渲染可操作农场。
- `1280x720`、`1440x900`、`1920x1080`、`2560x1440` 下不得出现控件重叠、文字溢出或空白 Phaser 画布。

## 12. 验收不变量

- 同一好友不能重复尝试同一茬；失败和被狗抓也算已尝试。
- 并发偷取不能超过本茬预算，`left_fruit_num` 永不为负。
- 主人收获与好友偷取并发时只能按锁顺序各结算一次，总果实守恒。
- Worker 重试、刷新和相同幂等键不能重抽事件、收获档或偷取结果。
- 保护期、每日限制和榜单边界在精确边界值有自动测试。
- 所有偷取 Token 包可以追溯到 Planting、Steal Attempt、规则版本和随机审计值。
